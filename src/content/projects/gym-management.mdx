## Overview

A side project with a friend (I wrote most of the code): a gym platform with separate experiences
for admins, coaches and members. The repository is private; I am happy to demo it.

## What it does

- **Admin**: members, memberships and plans, coaches, the weekly class schedule and payments.
- **Coach**: an exercise library, workout programmes for clients, classes to run.
- **Member**: self-registration from a phone, class discovery and booking, and check-in by scanning
  a QR code at the door within a configurable window.

## Engineering notes

- **Data model first.** A written ER design separates identity (`users`) from gym-specific roles
  and profiles, so one person can be a member at one gym and a coach at another.
- **API contract between front end and back end.** A hand-off document fixes endpoints and payloads
  so the Flutter screens and FastAPI routers can be built in parallel.
- **Tested back end.** 338 pytest tests cover the domain APIs; Playwright covers admin and member
  flows in the browser.
- **Repeatable environments.** Docker images behind Caddy, provisioned with Terraform and cloud
  templates. Staging can be rebuilt from scratch with seed data.
